# shcomp 0.0.2

fish support, discoverability, and a settled CLI. shcomp is pre-v1, and this
release breaks v0.0.1 where noted below; `CHANGELOG.md` has the full list.

Released 2026-11-18.

## Highlights

- fish: one `fish_complete_path` line, a loader that follows a `PATH` version
  switch between Tabs without forking `shcomp` on a warm Tab, and
  `complete-word --shell fish`. `[settings].shells` defaults to zsh and fish.
- `shcomp search` finds a tool across the embedded, user, and inline
  registries, with `--interactive` to pick one and add it.
- `shcomp add` finishes the job: it writes the selection and the shims, fetches
  URL sources, and prints the loading lines. `--dry-run` shows what it would do.
- `kind = "usage"` sources render a completion from a tool's usage KDL spec
  through the `usage` CLI, cached per binary.
- `ls` is a table that fits the terminal, and `doctor` is a sectioned report;
  both have `--json`. `doctor --check` runs one real completion per tool.
- `-v`/`-q`, `SHCOMP_LOG`, and `SHCOMP_LOG_FILE` trace resolution, generation,
  and reconciliation.
- A vendor zsh completion with an unquoted `_arguments` exclusion group, such
  as gradle's, no longer aborts.

## Breaking changes

- `shcomp completion <shell> --install` is removed; `shcomp install` writes
  shcomp's own completion with every other shim. Run `shcomp install` after
  upgrading.
- `ls --json` replaces `cached` / `mise_owned` with `cache { state, script, key }`
  and `owner`.
- `doctor` exits 1 when a check fails.
- `add` reconciles by default; `--no-install` keeps the old behavior.
- Commands mise installed from a packslip are no longer skipped: shcomp writes
  its own shim, and `doctor` reports the overlap.

## Install

```toml
[tools]
"packslip:github.com/dxkbroom/shcomp" = "0.0.2"
```
