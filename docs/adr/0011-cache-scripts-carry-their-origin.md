# Cache scripts carry their origin; loads record their outcome on the cold path

The cache key (ADR-0002) is a hash, so a directory of cached scripts cannot say which binary produced each one, whether that binary still exists, or why a completion silently stopped working. v0.0.3 writes two small JSON files beside the cache, both only on the cold path. Each script gets a sidecar `<key>.json` with the command, shell, real binary path, source kind, and creation time, written by the same call that writes the script; `clean --stale` uses it to remove scripts whose binary is gone or whose key no longer matches, and a script without one is stale by definition. `shcomp load` records its outcome per shell and command under `state/<shell>/<command>.json`: the key, the time, and `ok` or the error plus the first stderr line of the generator. It rewrites the record only when the outcome or key changes, so a session that loads an already-warm script reads one small file and writes nothing. `doctor` reads these records to report recent failures and a shell whose shims have never loaded. The zsh warm path never calls `shcomp`, and the fish warm path forks no `shcomp`, so neither pays for any of this. Keeping the files under the cache directory means `shcomp clean` removes them with the scripts; they are diagnostics, not configuration.
