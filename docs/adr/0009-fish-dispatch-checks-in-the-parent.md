# Fish dispatch checks in the parent shell

Fish has no per-command completion function to capture: it has a global registry of `complete` rules that the shell evaluates at Tab time. So ADR-0004's trick — source the vendor script once, keep the function, call it directly — has no fish equivalent, and the two honest designs are an autoloaded file that registers rules once per session (fast, but a version switch is invisible until a new shell) or a dynamic rule whose function runs at every Tab (always current, but the vendor script has to be re-read somewhere). shcomp takes the dynamic rule and gets the cost down by splitting it: the loader runs in the user's own fish, uses the builtin `command -s` and `test -nt` against remembered globals to notice a new binary or a newer script, calls `shcomp load` only when it notices, and then spawns one child `fish --no-config` with `fish_complete_path` cleared to source the cached script and answer `complete --do-complete`. A warm Tab therefore forks one child fish and no shcomp, while a version switch in another directory is followed at the next Tab. mise's stub does the same thing but asks `mise completion` on every Tab as well; the parent-side check is the part we improve on. The child is not optional: sourcing a vendor script in the user's shell would leave its helper functions and its `complete` registrations behind, and fish's registry has no scoped equivalent of zsh's `_comps`.
