# `install` prewarms by default

A completion script is generated the first time a Tab needs it, which makes the first Tab after an install or a version switch the slowest one: it forks `shcomp load`, which runs the vendor generator, under the user's cursor. `install` and `add` already run with the user waiting, with the network allowed (ADR-0005), and with every selected binary resolvable on the current `PATH`, so v0.0.3 generates there by default and the first Tab finds a warm cache. `--no-prewarm` and `[settings].prewarm = false` opt out for a user whose generators are slow or who installs on a machine where the tools are not yet on `PATH`. A prewarm failure is reported in the install summary and does not fail the install: the shim is still written, and the cold path still generates at Tab time, so a broken generator costs what it cost before. A version switch after install still pays one cold load; prewarming every mise-installed version was rejected because it runs generators for binaries the user may never call.
