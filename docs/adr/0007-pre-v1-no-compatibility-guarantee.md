# Pre-v1 releases promise no compatibility

shcomp is not at 1.0, and 0.0.2 says so in the README: the CLI, configuration, storage format, and behavior are not finalized, and a release may require configuration or cached data to be updated. That is what lets 0.0.2 replace v0.0.1's `ls --json` shape, remove `completion --install`, and make `add` reconcile, instead of carrying a compatibility layer for a file format nobody has depended on for more than a week. The obligation this creates is honesty, not stability: every break is listed in `CHANGELOG.md` under the version that makes it, and the README notice sits where a new user reads the install instructions. A compatibility promise before 1.0 would freeze a design that is still being found, and a silent break would be worse than either.
